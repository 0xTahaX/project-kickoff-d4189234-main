# دارا

پایهٔ MVP مدیریت مالی شخصی فارسی با رابط React/TypeScript/Vite، API مبتنی بر Express/TypeScript، Prisma و PostgreSQL. داشبورد JavaScript در `/legacy/` نگه داشته شده است. ثبت‌نام و ورود با نام کاربری و گذرواژه انجام می‌شود و ایمیل اختیاری است؛ کاربر مهمان هم می‌تواند بدون حساب و فقط روی همان مرورگر از برنامه استفاده کند.

## نیازمندی‌ها

- Node.js نسخهٔ 22.13 یا جدیدتر و npm.
- PostgreSQL محلی یا سروری برای اجرای API.

## راه‌اندازی محلی

1. نصب وابستگی‌ها:

   ```powershell
   npm.cmd install
   ```

2. ساخت فایل تنظیمات:

   ```powershell
   Copy-Item .env.example .env
   ```

3. PostgreSQL را نصب/راه‌اندازی کنید یا برای Supabase از صفحهٔ **Connect** رشتهٔ اتصال را بگیرید. برای کامپیوتری که فقط IPv4 دارد، از Session Pooler استفاده کنید؛ رشته را فقط در `DATABASE_URL` داخل `.env` ریشه قرار دهید. اگر رمز نویسه‌های رزروشده مثل `+`, `#`, `?`, `&` یا فاصله دارد، آن‌ها را در بخش رمز URL-encode کنید. `.env` نباید commit شود. برای Supabase گواهی رسمی را از **Database Settings → SSL Configuration → Download certificate** بگیرید، فایل را خارج از repository نگه دارید و مسیر مطلق آن را در `DATABASE_SSL_CA_FILE` تنظیم کنید. API اعتبار گواهی و نام میزبان را با TLS بررسی می‌کند؛ Prisma CLI نیز TLS اجباری و بررسی سخت‌گیرانهٔ گواهی را فعال می‌کند. هیچ‌گاه بررسی گواهی را غیرفعال نکنید.

   ثبت‌نام و ورود به ایمیل نیاز ندارند؛ فقط بازیابی گذرواژه به آن وابسته است. **در Render Free پورت‌های SMTP (25/465/587) مسدود هستند**، بنابراین در production از API روی HTTPS استفاده می‌شود: `BREVO_API_KEY` (حساب رایگان Brevo) و `MAIL_FROM` (نشانی فرستندهٔ تأییدشده). جزئیات دریافت کلید در [.env.example](./.env.example) آمده است. برای توسعهٔ محلی یا میزبانی که SMTP را باز می‌گذارد، همان `SMTP_HOST`/`SMTP_PORT`/`SMTP_SECURE`/`SMTP_USER`/`SMTP_PASS`/`SMTP_FROM` کار می‌کند و `MAIL_FROM` در صورت خالی‌بودن از `SMTP_FROM` خوانده می‌شود. بدون هیچ ترابری، مسیر بازیابی گذرواژه با خطای روشن `EMAIL_NOT_CONFIGURED` پاسخ می‌دهد، اما ثبت‌نام و ورود کار می‌کنند. ایمیل در فرم ثبت‌نام اختیاری است و فقط برای همان بازیابی استفاده می‌شود.

   در Supabase فقط وقتی هزینه صفر تضمین می‌شود که **Organization روی Free plan** باشد و سهمیه‌ها رعایت شوند؛ Nano بودن compute به‌تنهایی تضمین کافی نیست، چون در Organization پولی Nano هم هزینه دارد. طبق مستندات فعلی Supabase، Free شامل حداکثر دو پروژهٔ فعال، ۵۰۰ مگابایت دیتابیس برای هر پروژه، ۵ گیگابایت egress و ۱ گیگابایت storage است؛ پروژه پس از یک هفته بی‌فعالیتی ممکن است pause شود و backup خودکار در دسترس نیست. این طرح برای توسعه مناسب است، اما برای دسترس‌پذیری production یا بازیابی داده تضمین کافی نمی‌دهد. هیچ ارتقا یا قابلیت پولی را فعال نکنید.

4. بررسی اتصال به دیتابیس (این فرمان داده یا schema را تغییر نمی‌دهد):

   ```powershell
   npm.cmd run db:check --workspace=apps/api
   ```

5. تولید Prisma Client و اعمال migration (فقط پس از بررسی اتصال و اطمینان از دیتابیس مقصد):

   ```powershell
   npm.cmd run db:generate
   npm.cmd run db:migrate
   ```

برای بررسی صحت اتصال برنامه بعد از راه‌اندازی API، `/api/health` یک `SELECT NOW()` اجرا می‌کند و در صورت قطع بودن دیتابیس پاسخ `503` می‌دهد. API از یک pool با سقف پیش‌فرض ۵ اتصال برای هر process استفاده می‌کند؛ مقدار را با `DATABASE_POOL_MAX` در `.env` می‌توان بین ۱ تا ۲۰ تنظیم کرد. برای استقرار serverless سقف را با تعداد instanceها و محدودیت connection دیتابیس هماهنگ کنید.

6. اجرای API و وب در دو ترمینال فرزند:

   ```powershell
   npm.cmd run dev
   ```

   رابط Vite در `http://localhost:5173` و API در `http://localhost:3001` اجرا می‌شوند. Vite درخواست API را پراکسی می‌کند.

اگر PostgreSQL در دسترس نیست، برای اجرای داشبورد مهمان `npm.cmd run dev:web` را اجرا کنید؛ این پیش‌نمایش به API یا پایگاه‌داده نیاز ندارد و اطلاعات فقط در localStorage همان مرورگر می‌مانند. ثبت‌نام، ورود و همگام‌سازی سروری با این حالت در دسترس نیستند.

## دارایی‌ها و سرمایه‌گذاری

- در «دارایی‌ها» می‌توان نقد/سپرده، فلزات گران‌بها، سهام، صندوق، رمزارز، ملک، خودرو، ارز خارجی و سایر دارایی‌های دستی را ثبت کرد. بهای خرید خالی یعنی نامشخص است و با مقدار صفر تفاوت دارد. تاریخچهٔ ارزش‌گذاری حفظ می‌شود؛ قیمت‌های بیش از ۳۰ روز به‌عنوان قدیمی مشخص می‌شوند.
- در «ارزش خالص»، موجودی حساب‌های موجود، دارایی‌ها و بدهی‌ها بر اساس ارز جداگانه نمایش داده می‌شوند. تبدیل فقط با نرخ دستی همراه با منبع و زمان انجام می‌شود؛ نرخ قدیمی‌تر از ۳۰ روز قابل استفاده نیست. دارایی‌ای که ارزش آن در موجودی حساب لحاظ شده باید علامت‌گذاری شود تا دوباره شمرده نشود.
- سبد سرمایه‌گذاری از lotهای FIFO و فروش جزئی، کارمزد خرید/فروش، سود نقدی، سپرده/برداشت نقدی، انتقال lot و تعدیل تعداد پشتیبانی می‌کند. خرید/فروش ثبت‌شده در سبد را دوباره به‌عنوان هزینه/درآمد عادی ثبت نکنید. اگر تراکنش به حساب نقدی وصل نشود، اثر آن در دفتر نقدی داخلی سبد ثبت می‌شود.
- بازده قیمت ساده، سود تحقق‌یافته و تحقق‌نیافته و سود نقدی جداگانه گزارش می‌شوند. بازده زمان‌وزن و پول‌وزن ارائه نمی‌شود؛ موجودی تاریخی حساب‌های عادی نیز ذخیره نشده و بنابراین نمودار تاریخی فقط سبد سرمایه‌گذاری را پوشش می‌دهد.
- ارزش‌گذاری‌های دفتر دارایی‌ها همچنان دستی‌اند و قیمت بازار به‌طور خودکار تاریخچهٔ دارایی‌های شخصی را تغییر نمی‌دهد. API به PostgreSQL نیاز دارد و هنوز مالکیت/احراز هویت فعال ندارد؛ داده‌های مهمان در سرور یا بین دستگاه‌ها همگام نمی‌شوند.
- هیچ کلید API به مرورگر داده نمی‌شود. دریافت بازار فقط برای نمادها و واحدهای ذکرشده در بخش «بازارها» فعال است؛ سایر دارایی‌ها قیمت آنلاین ندارند.

## بلاک‌چین و ژورنال معاملات

- بخش «بلاک‌چین» در این MVP فقط Ethereum Mainnet را با endpoint عمومی [Blockscout API v2](https://eth.blockscout.com/api/v2) می‌خواند: موجودی ETH، موجودی توکن‌های ERC-20، حداکثر ۵۰ تراکنش آخر و حداکثر ۵۰ انتقال توکن آخر برای هر همگام‌سازی. تراکنش بومی، انتقال ERC-20 و تعامل قرارداد به شکل عمومی نمایش داده می‌شوند؛ NFT، trace/internal transaction، رمزگشایی رویداد قرارداد و تشخیص staking پشتیبانی نمی‌شوند. اگر provider صفحهٔ بعدی یا دادهٔ ناقص گزارش کند، هشدار ناقص‌بودن نشان داده می‌شود؛ صفحه‌های بعدی فعلاً واکشی نمی‌شوند. درخواست‌ها فقط‌خواندنی‌اند و API key لازم ندارند.
- نشانی عمومی مدرک مالکیت نیست. دارایی‌های کیف‌پول به ارزش خالص یا سبد سرمایه‌گذاری اضافه نمی‌شوند تا با حساب‌ها/دارایی‌های ثبت‌شده دوباره‌شماری نشوند. دسته‌بندی تراکنش فقط برای مرور است؛ واریز، برداشت، swap، تعامل قرارداد و کارمزد خودکار به درآمد/هزینه تبدیل نمی‌شوند. انتقال داخلی فقط وقتی دو نشانی ثبت‌شده به هم انتقال دهند به‌طور احتمالی علامت می‌خورد و همچنان قابل بازبینی است.
- فهرست کیف‌پول‌ها، تراکنش‌های واردشده و ژورنال معاملات در localStorage مرورگر همین دستگاه می‌مانند؛ همگام‌سازی چنددستگاهی، احراز مالکیت و پشتیبان سروری ندارند. عبارت بازیابی، کلید خصوصی، گذرواژه یا مجوز برداشت هرگز درخواست/ذخیره نمی‌شود. قیمت و موجودی زنجیره‌ای، محاسبات دارایی/سرمایه‌گذاری Phase 3 را تغییر نمی‌دهد.
- ژورنال معاملات دستی از حجم‌های جزئی، جهت Long/Short، معاملات نقدی/مشتقه، هزینه‌های ورود/خروج، هزینهٔ تأمین مالی ثبت‌شده، استراتژی، یادداشت و ارزیابی رعایت برنامه پشتیبانی می‌کند. کارمزد ورود متناسب با حجم هر خروج تخصیص می‌یابد؛ سود تحقق‌یافتهٔ خالص، قیمت تحقق‌نیافته، هزینه‌ها و معیارها جدا هستند. نرخ برد فقط معاملات کاملاً بسته را در مخرج می‌گیرد؛ break-even شمرده می‌شود اما برد نیست؛ میانگین باخت علامت منفی دارد؛ Profit Factor بدون زیان قابل محاسبه نیست و خالی می‌ماند.
- قیمت باز معامله فقط دستی، همراه منبع و زمان ثبت می‌شود؛ بعد از ۲۴ ساعت قدیمی علامت می‌خورد. افت سرمایه فقط با سرمایهٔ آغازین مثبت و معاملات بستهٔ مرتب‌شده محاسبه می‌شود. ارزهای متفاوت هرگز در یک گزارش جمع نمی‌شوند؛ فیلتر ارز لازم است. بازده زمان‌وزن/پول‌وزن، توصیهٔ سرمایه‌گذاری، قیمت خودکار معاملات، اتصال/اجرای صرافی، import صرافی، آپلود نمودار، استیکینگ/پاداش خودکار و زنجیره‌های غیر Ethereum در این نسخه پشتیبانی نمی‌شوند.
- دریافت واقعی اطلاعات کیف‌پول فقط وقتی کار می‌کند که API سرور اجرا شود: در توسعه `npm.cmd run dev` (به تنظیم PostgreSQL موجود پروژه نیاز دارد). `npm.cmd run dev:web` برای پیش‌نمایش وب است و بدون API، همگام‌سازی زنجیره‌ای در دسترس نیست. Blockscout عمومی است و تأخیر/دسترسی، نرخ محدودیت و کامل‌بودن داده تضمین نمی‌شود؛ snapshot بیش از ۵ دقیقه قدیمی برچسب می‌گیرد و خطای sync آخرین snapshot را فقط با زمان قبلی آن نشان می‌دهد.

## بازارها

- صفحهٔ مستقل «بازارها» نرخ دلار آمریکا در بازار آزاد، گرم طلای ۱۸ عیار، اونس تروا طلا و نقره به دلار، و گرم نقرهٔ ۹۹۹ ایران را نشان می‌دهد. اونس جهانی نقره با «هر گرم نقرهٔ ایران» یکی نیست. فید قیمت خرید/فروش جداگانه ارائه نمی‌کند.
- API سرور از endpoint عمومی [`latest-toman.json`](https://raw.githubusercontent.com/iran-market/iran-market.github.io/main/data/latest-toman.json) در [Iran Market Data](https://iran-market.github.io/) استفاده می‌کند. دریافت بدون API key است؛ مستندات منبع به‌روزرسانی هر ۳۰ دقیقه و cache پنج‌دقیقه‌ای برای Raw GitHub را اعلام می‌کند. فایل شامل قیمت‌های ایران با واحد تومان (`IRT`) و دارایی‌های جهانی با ارز اصلی (از جمله اونس طلا/نقره با USD) است؛ برچسب‌ها و واحدهای هر نماد پیش از نمایش کنترل می‌شوند.
- وضعیت «قدیمی» در Dara برای قیمت‌های بیش از ۹۰ دقیقه، دادهٔ stale منبع یا خطای تازه‌سازی نمایش داده می‌شود. تغییر قیمت فقط وقتی قیمت پایانی قبلی معتبر باشد، نسبت به همان قیمت محاسبه می‌شود. آخرین پاسخ معتبر فقط در حافظهٔ API نگهداری می‌شود و با راه‌اندازی مجدد سرور پاک خواهد شد؛ تاریخچه در دیتابیس ذخیره نمی‌شود.
- درخواست بیرونی فقط از API سرور انجام می‌شود؛ فایل کامل فید در بررسی فعلی حدود ۰٫۹ مگابایت بود و تا پنج دقیقه در حافظه cache می‌شود (حداکثر حدود ۲۸۸ درخواست بیرونی در روز برای هر process در صورت تقاضای پیوسته). timeout ده‌ثانیه‌ای و سقف اندازهٔ پاسخ اعمال می‌شود. API key یا credential در مرورگر وجود ندارد. اجرای کامل در توسعه/استقرار همچنان به API موجود نیاز دارد؛ API پروژه هنگام شروع به `DATABASE_URL` متصل می‌شود.
- گزینه‌های بررسی‌شده: [طلاسنج](https://talasanj.info/توسعه‌دهندگان) در بررسی فعلی 404 داد؛ [نِت اَرز](https://netarz.ir/rates) تابلوی عمومی نرخ دارد اما مستند API عمومی و مجوز استفادهٔ ماشینی تأیید نشد؛ مستند [EZRate](https://ezrate.me/api/ar) پلن رایگان ۱٬۵۰۰ درخواست ماهانه/۵۰ روزانه با تازگی ۳۰ دقیقه را معرفی می‌کند اما API بدون کلید 401 داد. در نتیجه هیچ‌کدام در این نسخه متصل نیستند.
- Iran Market Data استفادهٔ رایگان برای پروژه‌های عمومی و مجوز MIT برای مخزن را اعلام می‌کند، اما شرایط مستقل و صریحی برای بازنشر تجاری دادهٔ بالادستی، تضمین دقت یا SLA پیدا نشد. با وجود انتساب منبع در UI، پیش از استفادهٔ تجاری/در مقیاس عمومی باید مجوز داده و شرایط TGJU/منبع را جداگانه تأیید کنید. قیمت‌ها مرجع و اطلاع‌رسانی‌اند، نه نرخ رسمی، قیمت تضمین‌شدهٔ معامله یا توصیهٔ سرمایه‌گذاری.

## فرمان‌های روزمره

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run db:validate
npm.cmd run test:e2e
```

`npm.cmd test` در دسترس نبودن مسیرهای ورود/ثبت‌نام API، محاسبات مالی، cache provider و تست‌های وب/legacy را بررسی می‌کند؛ اجرای migration روی PostgreSQL واقعی جداگانه لازم است.
آزمون Playwright مسیرهای قدیمی حساب و ثبت دارایی/رویداد سرمایه‌گذاری را بررسی می‌کند؛ برای آن فقط Chromium (`npx playwright install chromium`) لازم است.

## دستیار، یادآورها و تبادل داده

- دستیار در `/legacy/` ترجیحات مالی را جدا از پروفایل مالی ذخیره می‌کند و فقط جمع درآمد/هزینه، بودجه و بیشترین هزینه‌های بازه را با محاسبات محلی نشان می‌دهد. هیچ مدل زبانی پیکربندی نشده و هیچ داده‌ای برای تحلیل به سرویس AI ارسال نمی‌شود؛ حتی انتخاب رضایت بیرونی در این نسخه صرفاً ترجیح آینده است. route وضعیت AI فقط وضعیت تنظیم را می‌دهد. ورود و منبع مجاز دادهٔ کاربر به API دستیار متصل نیست.
- یادآورها هنگام مشاهدهٔ صفحه از بودجه، موعد تکرارشونده و درصد هدف پس‌انداز ساخته می‌شوند و در همان مرورگر قابل خواندن/تنظیم‌اند. زمان‌بندی پس‌زمینه، push، ایمیل و پیامک وجود ندارد.
- CSV تراکنش با سقف یک مگابایت و ۵۰۰۰ ردیف پیش‌نمایش و اعتبارسنجی می‌شود؛ ورود با اقدام جداگانهٔ کاربر انجام می‌شود. قالب پشتیبانی‌شده `date,type,amount,account,category,description,note,targetAccount` است؛ نوع‌های مجاز `income`, `expense`, `transfer` هستند. مبلغ مثبت و تاریخ معتبر ISO لازم است. نام حساب/دسته در پیش‌نمایش قابل نگاشت است و ردیف تکراری بر اساس فیلدهای تراکنش نادیده گرفته می‌شود. CSV تراکنش و پشتیبان JSON محلی قابل دانلود است؛ واردکردن پشتیبان JSON فعال نیست.
- پاک‌سازی داده فقط اطلاعات Dara در localStorage همین مرورگر را حذف می‌کند؛ حذف حساب، نشست یا دادهٔ سروری وجود ندارد. خانواده/حساب مشترک، مالیات، بیمه، بازنشستگی، گزارش دوره‌ای و اعلان خارجی deferred هستند.
- حریم خصوصی و محدودیت‌ها در [اعلامیهٔ حریم خصوصی](./apps/web/public/legacy/privacy.html) شرح داده شده‌اند.

## تنظیمات محیطی

همهٔ نام‌ها و نمونه‌های امن در [.env.example](./.env.example) هستند:

- `DATABASE_URL`: اتصال PostgreSQL.
- `DATABASE_SSL_CA_FILE`: مسیر مطلق گواهی CA برای Supabase (خارج از repository).
- `PORT`: پورت API، پیش‌فرض `3001`.
- `WEB_ORIGIN`: مبدأ مجاز مرورگر و بررسی CSRF.
- `BREVO_API_KEY` و `MAIL_FROM`: ارسال ایمیل بازیابی گذرواژه از طریق API روی HTTPS (برای Render Free).
- `SMTP_*`: ترابری جایگزین برای توسعهٔ محلی یا میزبانی که SMTP را باز می‌گذارد.

مقادیر واقعی را فقط در `.env` محلی یا secret manager استقرار قرار دهید؛ `.env` در Git نادیده گرفته می‌شود.

## داده و مهاجرت

- schema و migrationهای دیتابیس در `apps/api/prisma` هستند. تغییر schema را با migration نسخه‌بندی کنید؛ از `db:push` در استقرار استفاده نکنید.
- نام کاربری شناسهٔ ورود است، پیش از ذخیره و جست‌وجو کوچک‌حرف و یکسان می‌شود و باید با حرف شروع شود؛ حرف، عدد، نقطه، خط تیره و زیرخط مجاز است. ثبت‌نام بلافاصله نشست می‌سازد و نیازی به تأیید ایمیل یا SMTP ندارد. ایمیل اختیاری است و فقط برای بازیابی گذرواژه نگه داشته می‌شود. نشست‌ها در کوکی HttpOnly و جدول نشست‌ها نگهداری می‌شوند؛ توکن نشست و لینک بازیابی به‌صورت hash در دیتابیس ذخیره می‌شوند. ورود Google در آینده اضافه می‌شود و ستون‌های ایمیل/گذرواژه از همین حالا اختیاری‌اند.
- تراکنش‌ها، حساب‌ها و دسته‌بندی‌ها در جدول‌های PostgreSQL و با شناسهٔ مالک ذخیره می‌شوند. سایر داده‌های ساختاریافتهٔ داشبورد در `user_workspace` به تفکیک کاربر ذخیره و بین دستگاه‌ها همگام می‌شوند؛ هر بخش سقف ۵۱۲ KiB دارد.
- فضای مهمان جدا از حساب کاربری است و خودکار به حساب منتقل نمی‌شود. اطلاعات مهمان فعلی فقط در مرورگر همان دستگاه باقی می‌ماند.
- مبلغ‌ها `Decimal(20, 6)` هستند، timestampها UTC و currencyها کد سه‌حرفی ISO هستند.
- نسخهٔ قدیمی رابط در مسیر `/legacy/` حفظ شده است؛ localStorage در حساب واردشده فقط cache است و در صورت شکست sync، خطا در رابط نشان داده می‌شود.

## استقرار

### استقرار رایگان آزمایشی در Render + Supabase

فایل `render.yaml` سرویس Node وب/API را روی پلن Free تعریف می‌کند. دامنهٔ رایگان سرویس به شکل `https://<نام>.onrender.com` است؛ دامنهٔ `.com` اختصاصی رایگان نیست.

1. مخزن را در GitHub قرار دهید و در Render گزینهٔ **New → Blueprint** را برای مخزن انتخاب کنید.
2. در Supabase یک پروژه با **Organization روی Free plan** بسازید؛ از **Connect** رشتهٔ اتصال PostgreSQL را بردارید. برای سازگاری شبکه از Session Pooler استفاده کنید.
3. فایل CA رسمی Supabase را در Render بخش **Environment → Secret Files** با نام `supabase-prod-ca-2021.crt` بارگذاری کنید و `DATABASE_SSL_CA_FILE` را روی `/etc/secrets/supabase-prod-ca-2021.crt` بگذارید.
4. مقدارهای `DATABASE_URL` و `DATABASE_SSL_CA_FILE` را در Environment سرویس Render وارد کنید. برای ایمیل بازیابی گذرواژه، `BREVO_API_KEY` و `MAIL_FROM` را بگذارید (SMTP روی پلن Free مسدود است). `APP_URL` در صورت خالی‌بودن از `RENDER_EXTERNAL_URL` Render گرفته می‌شود.
5. Render migrationهای ثبت‌شده را هنگام شروع سرویس اعمال می‌کند و `/api/health` را بررسی می‌کند. پس از Deploy، دامنهٔ نمایش‌داده‌شده در داشبورد Render را باز کنید و در مرورگر ثبت‌نام و ورود با نام کاربری را بیازمایید.
6. برای درخواست ایندکس رایگان، دامنه را در [Google Search Console](https://search.google.com/search-console/) ثبت و از URL Inspection درخواست crawl کنید. ایندکس‌شدن و رتبه تضمینی یا فوری نیست.

Render Free سرویس وب را پس از ۱۵ دقیقه بی‌ترافیکی متوقف می‌کند و بازشدن بعدی ممکن است حدود یک دقیقه طول بکشد. Supabase Free نیز در صورت یک هفته بی‌فعالیتی می‌تواند pause شود، سهمیه و نگهداری محدود دارد و backup خودکار ندارد. بنابراین این ترکیب برای نمونه و آزمایش رایگان است، نه میزبانی قابل‌اتکای اطلاعات مالی production. قبل از استفادهٔ واقعی، سیاست پشتیبان‌گیری و حریم خصوصی را هم بررسی کنید.
